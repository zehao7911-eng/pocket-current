# GameWave import

Upload POCKET-CURRENT.zip with index.html at the root. Normal browsers and GitHub Pages start independently of window.neonlib.

The first accepted water pulse starts a tray session. The final ring finishes its physical slide before gameOver is called. Menus, reward viewing and cosmetic changes do not invent a new round. Restart or changing trays ends an active attempt. Restoring an idle partial tray starts on the next genuine pulse. Explicitly resuming a saved moving ring continues its real session.

Only pocket-current's profile is uploaded. The exact active ring checkpoint remains local in pocket-current-v1. Best times merge by minimum, medals by maximum and durable reward flags by union. Other games' saves are never enumerated, copied or cleared.

A confirmed positive like unlocks gold pump rims. A successful direct comment unlocks prism bubbles. Both are optional saved cosmetics. The adapter validates direct payloads and string project IDs, ignores unlikes, accepts an empty image-comment string, checks asynchronous registration code 0, guards repeat rewards and disposes subscriptions. A late asynchronous registration only updates its isolated social section so it cannot replace an active Resume button.

SDK absence, partial and late injection, rejected calls, serial save timeouts, cleanup, genuine controller transitions and resumed partial trays are tested with controlled mocks. A rejected asynchronous viewport falls back to browser sizing. SDK density does not scale CSS viewport dimensions.

The official [GameWave SDK documentation](https://rg975ojk5z.feishu.cn/wiki/MQg7wMknzieOkukxyWVc4UB0nDh) was checked on November 8, 2026 and displays the October 30 revision. Real supported GameWave App import, live account cloud persistence and actual social callbacks require host-side testing.
